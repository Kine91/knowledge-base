ECS, Fargate i EC2 — compute deep dive

Task lifecycle, deployment, capacity, networking i kontenery

1. Task definition, task i service2. CPU, pamięć, dysk, sieć3. Rolling deployment i graceful shutdown4. Autoscaling i wybór sygnału5. EC2 i koszty operacyjne6. DiagnostykaPraktyka

1. Task definition, task i service

Task definition to wersjonowany opis kontenerów, zasobów, portów, health checks, volume i ról. Task jest instancją; service utrzymuje desired count i zastępuje zakończone taski. ECS scheduler rozmieszcza zadania na capacity providers. Fargate dobiera izolowane środowisko do wspieranej kombinacji CPU/RAM, EC2 wymaga wolnej pojemności na hostach. Task execution role służy agentowi (ECR, logi, sekrety przy starcie); task role jest tożsamością kodu. Nie przekazuj statycznych access keys przez environment.

2. CPU, pamięć, dysk, sieć

CPU units 1024 odpowiadają 1 vCPU; limity/udziały kontenerów i throttling zależą od platformy. Memory hard limit może zakończyć kontener OOM, nawet gdy V8 heap nie jest pełny (Buffer/native allocations). Ustaw Node heap poniżej limitu i obserwuj RSS. Fargate używa awsvpc: ENI/IP per task, co oznacza zużycie adresów subnetu podczas autoscalingu i deploymentu. Public subnet bez public IP nie daje internetu; ECR pull wymaga NAT lub odpowiednich endpoints (ECR API/DKR, S3, logi). Ephemeral storage znika po zakończeniu taska. Do trwałych danych użyj zewnętrznego storage.

3. Rolling deployment i graceful shutdown

ECS może uruchamiać nowe taski przed zatrzymaniem starych; minimumHealthyPercent i maximumPercent wyznaczają granice. Przykład desired=10, max=200%: przejściowo do 20 tasków, zatem pool DB i subnet capacity muszą wytrzymać overlap. Readiness sprawdza gotowość do obsługi, liveness nie powinien restartować wszystkich tasków przy krótkiej awarii DB. ALB deregistration delay, SIGTERM i stopTimeout uzgodnij z czasem requestów. Proces PID 1 musi odbierać sygnały; exec form CMD w Dockerfile. Po SIGTERM przerwij intake, dokończ pracę w deadline, zwolnij zasoby. Circuit breaker/alarms wykrywają nieudany deploy; rollback nie cofa danych.

4. Autoscaling i wybór sygnału

Target tracking CPU działa dla CPU-bound API, ale worker może być I/O-bound. Queue backlog per task = visible messages / running tasks; sensowny target = acceptable queue latency / średni czas zadania (jeśli jedna praca na task; uwzględnij concurrency). Autoscaling ma opóźnienie provisioning i cooldown. Ustal max task count wynikający z budżetu DB i SAP. Fargate Spot może zostać przerwany; worker musi bezpiecznie ponowić pracę, API krytyczne utrzymuje bazową pojemność on-demand. EC2 ASG i ECS capacity provider mają dwie pętle skalowania; monitoruj pending tasks i braki capacity.

5. EC2 i koszty operacyjne

EC2 daje kontrolę nad AMI, rodzajem instancji, EBS, GPU i placement. ASG rozkłada instancje po AZ, launch template definiuje AMI i konfigurację; instance profile i IMDSv2 ograniczają dostęp do credentials. Wymieniaj hosty zamiast ręcznych zmian, używaj SSM zamiast otwartego SSH, patchuj i testuj immutable AMI. EBS jest związany z AZ; snapshot to kopia, nie automatyczny failover. Dla kontenerów EC2 uwzględnij bin packing i daemon overhead; Savings Plans/Spot porównuj z realną utylizacją. Fargate zmniejsza pracę operacyjną, nie eliminuje zadań związanych z image, networking i aplikacją.

6. Diagnostyka

Task PENDING: brak CPU/RAM, IP, quota lub capacity. STOPPED: sprawdź stoppedReason, exit code, logi, OOM, image pull, secrets i health checks. ALB 503: brak healthy targets; 502: reset/nieprawidłowa odpowiedź; 504: timeout. Dla sporadycznych resetów porównaj keep-alive timeout aplikacji z idle timeout LB. ECS Exec używaj z audytem, nie jako stałego sposobu zmiany produkcji. Wersjonuj image digest i testuj lokalnie na zgodnej architekturze x86_64/arm64.

Praktyka: kontener Node.js i draining

Fragment runtime stage; produkcyjne node_modules muszą pochodzić z kompatybilnej platformy. Pin digest w rzeczywistym pipeline, skanuj obraz i uruchamiaj jako non-root.

FROM node:22-alpine AS runtime
WORKDIR /app
COPY --chown=node:node dist/ ./dist/
COPY --chown=node:node node_modules/ ./node_modules/
USER node
CMD ["node", "dist/main.js"]

W ECS ustaw stopTimeout adekwatny do drain, ALB deregistration delay i application timeout uzgodnij. Worker przestaje pollować przed shutdown, nie potwierdza niedokończonych rekordów. Jeżeli praca przekracza deadline, redelivery musi być bezpieczne.
