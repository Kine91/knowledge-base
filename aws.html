AWS: wybór usług i architektura

API Gateway, Lambda, ECS Fargate, EC2, S3, IAM

Zagadnienie 1 / 5

API Gateway + Lambda

Dobry wybór dla zmiennego ruchu i krótkich, bezstanowych zadań. Kontroluj concurrency, throttling, payload/timeout, cold start i koszt wywołań.

Praktyka / decyzja projektowa

Przepływ: JWT authorizer → API Gateway → Lambda → RDS Proxy → Postgres. Walidacja wejścia i business authorization należą do aplikacji.

Pytanie senior / pułapka

API Gateway nie zastępuje kontroli dostępu do zasobów; throttling nie gwarantuje ochrony przed każdym wzorcem obciążenia.

Zagadnienie 2 / 5

Lambda vs Fargate vs EC2

Lambda: event-driven i bursty workloads; Fargate: kontenery, dłuższe procesy, stabilny serwis; EC2: większa kontrola OS i kosztów przy dobrze wykorzystanej flocie.

Praktyka / decyzja projektowa

Przy wielu workerach i połączeniach DB wybierz ECS/Fargate z autoscalingiem opartym na queue depth/age, a nie tylko CPU.

Pytanie senior / pułapka

Wyjaśnij trade-off kosztów, cold start, limity, operacyjność i długotrwałe połączenia.

Zagadnienie 3 / 5

VPC i PostgreSQL

Lambda w VPC nie oznacza automatycznie dostępu do Internetu. Security groups, subnety, NAT/VPC endpoints oraz routing są częścią projektu.

Praktyka / decyzja projektowa

RDS/Aurora w prywatnych subnetach; sekret w Secrets Manager; TLS i least-privilege. RDS Proxy pomaga ograniczać churn połączeń; transakcje/session state mogą powodować pinning.

Pytanie senior / pułapka

Policz globalny budżet połączeń: suma pooli wszystkich replik i workerów ≤ bezpieczny limit DB.

Zagadnienie 4 / 5

S3 i bezpieczeństwo

S3 to object storage, nie dysk POSIX. Używaj presigned URLs z krótkim TTL, server-side encryption, bucket policy i walidacji typu/rozmiaru uploadu.

Praktyka / decyzja projektowa

Frontend pobiera presigned POST/PUT, uploaduje bezpośrednio, backend zapisuje metadane i uruchamia skanowanie/przetwarzanie eventem.

Pytanie senior / pułapka

Nie traktuj Content-Type od klienta jako zaufanego. IAM deny i ekspozycja publiczna wymagają kontroli.

Zagadnienie 5 / 5

Infrastructure as Code

Terraform/CDK/CloudFormation zapewniają powtarzalne środowiska i review zmian. Rollback aplikacji i migracji bazy planuj oddzielnie.

Praktyka / decyzja projektowa

Pipeline: lint → unit → integration → build → security scan → deploy canary → metryki → promotion.

Pytanie senior / pułapka

Odpowiedz: jak odtwarzasz środowisko i wykrywasz drift?
