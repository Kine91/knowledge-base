Ćwiczenia na głos i plan przygotowania

1. System design: orders2. System design: dokumenty3. Code review case4. Plan 4 tygodnie
Zagadnienie 1 / 4

System design: orders

Zaprojektuj Orders API dla 5000 req/s, płatności, SAP i Postgres. Ustal SLA, consistency, critical path, failure modes, capacity i observability.

Praktyka / decyzja projektowa

Odpowiedź: API Gateway → Orders service → Postgres + outbox → SQS workers → SAP; read endpoints cache; idempotency key; DLQ i reconciliation.

Pytanie senior / pułapka

Dopytania: DB down? SQS down? timeouts? ten sam request 3 razy? deploy w trakcie przetwarzania?

Zagadnienie 2 / 4

System design: dokumenty

Zapewnij bezpieczny upload 2 GB, autoryzację i powiadomienie po przetworzeniu. Rozrysuj S3 presigned multipart upload, event handling, scanning, metadane i retry.

Praktyka / decyzja projektowa

Sprawdź limity API Gateway/Lambda zamiast przesyłać plik przez backend; lifecycle, checksum, cleanup abandoned uploads.

Pytanie senior / pułapka

Jak zapewnisz, że użytkownik nie odczyta cudzego pliku?

Zagadnienie 3 / 4

Code review case

Masz Promise.all(orders.map(save)), pool=100 per pod, 20 podów, brak timeout, retry na każdym poziomie. Wskaż ryzyka i zaproponuj limity.

Praktyka / decyzja projektowa

Budżet globalny DB, bounded concurrency, backoff+jitter, circuit breaker, observability; zmierz na produkcyjnych rozkładach.

Pytanie senior / pułapka

Co jest pierwszą zmianą, którą zmierzysz, a co rozwiązaniem długoterminowym?

Zagadnienie 4 / 4

Plan 4 tygodnie

Tydzień 1: Node/TS/Postgres + testy współbieżności. Tydzień 2: AWS/SQS/SNS/Lambda/Fargate + outbox. Tydzień 3: mikroserwisy/SAP + system design. Tydzień 4: React/performance + mock interviews.

Praktyka / decyzja projektowa

Codziennie: 45 min teorii, 60 min implementacji, 30 min odpowiedzi na głos; zapisuj luki jako nowe sekcje repo.

Pytanie senior / pułapka

Priorytet dla Twojego profilu React/Node: pogłębić AWS operations, messaging correctness i Postgres concurrency.
