Node.js i TypeScript — runtime i zaawansowane typowanie

Event loop, libuv, pamięć, streams, concurrency, typy i granice aplikacji

1. Event loop, libuv i scheduling2. Worker threads, processes i streams3. Concurrency, cancellation i błędy4. Pamięć, GC i diagnostyka5. TypeScript: structural typing i soundness6. Runtime validation, moduły i kontrakty7. Backend API i NestJS/Express

1. Event loop, libuv i scheduling

JS głównego isolate wykonuje jeden callback naraz. libuv obsługuje gotowość socketów przez OS, a część operacji (fs, dns.lookup, crypto, zlib) używa thread pool. Promise nie tworzy wątku. Fazy event loop: timers, pending callbacks, poll, check (setImmediate), close; szczegóły timerów zależą od wersji libuv. process.nextTick i microtask queue są opróżniane między callbackami; rekurencyjny nextTick lub microtasks mogą zagłodzić I/O. Kolejność top-level nextTick/Promise może się różnić CJS/ESM. setTimeout(fn,0) nie gwarantuje natychmiastowego wykonania. CPU-heavy JSON.parse, regex ReDoS, synchroniczne crypto blokują wszystkie requesty w procesie. Mierz eventLoopUtilization i monitorEventLoopDelay, nie tylko CPU. Zwiększenie UV_THREADPOOL_SIZE pomaga tylko jeśli pool jest bottleneckiem i host ma zasoby.

2. Worker threads, processes i streams

worker_threads mają osobny V8 isolate, komunikacja przez structured clone/transferable ArrayBuffer, SharedArrayBuffer wymaga synchronizacji Atomics. Pool workerów zamiast tworzenia jednego per request; koszt kopiowania może zdominować małe joby. Child process daje osobny OS process i failure domain. Scale horizontal przez kontenery, unikaj sticky state. Stream backpressure: writable.write() false → czekaj na drain, highWaterMark to próg buforowania, nie hard limit. pipeline propaguje błędy i sprząta streamy; nie bufferuj całego pliku.
import { pipeline } from "node:stream/promises";
import { createReadStream, createWriteStream } from "node:fs";
import { createGzip } from "node:zlib";
await pipeline(createReadStream("input"), createGzip(),
  createWriteStream("input.gz"), { signal });
Przy HTTP upload ogranicz rozmiar, waliduj content i reaguj na disconnect. S3 direct upload często usuwa cały ten bottleneck.

3. Concurrency, cancellation i błędy

Promise.all natychmiast planuje wszystkie wywołania z map; fail-fast nie anuluje pozostałych. allSettled zbiera wyniki, ale nie ogranicza concurrency. Użyj semafora/p-limit plus ograniczenia wejścia, bo nawet kolejka oczekujących promises zużywa RAM. AbortController przekazuj do API wspierających cancellation; Promise.race z timerem nie zatrzymuje side effect. Deadline propaguj do HTTP/DB; oddziel connect/read/overall timeout. Retry tylko idempotentne operacje z full jitter. EventEmitter error bez listenera może zakończyć proces. Unhandled rejection/uncaught exception traktuj jako ryzyko niespójnego procesu: loguj i kontrolowanie zakończ pod nadzorem, nie kontynuuj bezwarunkowo. Graceful shutdown: stop readiness/intake, drain requestów, stop poller, zamknij pool, deadline wymuszonego zakończenia.

4. Pamięć, GC i diagnostyka

RSS obejmuje heap, stack, native memory, Buffer i fragmentację. heapUsed rośnie i spada podczas GC; rosnący baseline po pełnych GC sugeruje retencję. V8 generational GC, young vs old generation, major GC może wydłużać p99. Ustaw max-old-space-size poniżej limitu kontenera, bo to nie limit RSS. Typowe leaki: global Map bez TTL, closures, listeners bez cleanup, timery, unresolved promises, ogromne cache. Heap snapshot porównuj po kontrolowanym obciążeniu; może zatrzymać proces i zwiększyć pamięć, wykonuj na replice lub środowisku diagnostycznym. CPU profile/flame graph wskazuje hot paths, async I/O wymaga trace. AsyncLocalStorage do correlation ID, nie do globalnego kontekstu bezpieczeństwa bez kontroli lifecycle. Monitoruj event loop delay, RSS, heap, GC, active handles, throughput, p99.

5. TypeScript: structural typing i soundness

TS jest structural i celowo nie w pełni sound. any wyłącza kontrolę, unknown wymusza narrowing; type assertion nie waliduje danych. strict, noUncheckedIndexedAccess, exactOptionalPropertyTypes pomagają wychwycić brak wartości (opcjonalne pole ≠ jawne undefined). readonly jest compile-time i płytkie, Object.freeze runtime też płytkie. Branded type chroni przed pomyleniem identyfikatorów po walidacji.
type Brand<T,B> = T & { readonly __brand: B };
type OrderId = Brand<string,"OrderId">;
type Result<T> =
  | { ok: true; value: T }
  | { ok: false; code: "NOT_FOUND" | "CONFLICT" };
function assertNever(x: never): never { throw new Error(String(x)); }
Discriminated unions modelują dozwolone stany zamiast boolean flag combinations; exhaustive switch z never. Generics preserve relację między typami, constraints ograniczają możliwe operacje; conditional types dystrybuują po naked union, [T] extends [U] zapobiega dystrybucji. mapped types, keyof, indexed access, infer, satisfies i as const pomagają zachować typy literalne. Nie buduj type-level frameworku, jeśli utrudnia czytelność i czas kompilacji.

6. Runtime validation, moduły i kontrakty

HTTP/SQS/SAP/DB są trust boundaries. Parsuj unknown przez schema (Zod/Valibot/JSON Schema), rozdziel walidację formatu od invariantów domeny i autoryzacji. Typy generowane z OpenAPI redukują drift, ale nie walidują runtime. DTO transportowe, domena i persistence mają różne lifecycle. Date/timezone, bigint i decimal: JSON nie serializuje bigint domyślnie, JS number traci precyzję dużych integer i pieniędzy; stosuj integer minor units w bezpiecznym zakresie lub decimal/string. ESM vs CJS: package type, exports, import resolution i TS moduleResolution NodeNext; testuj rzeczywisty output, nie tylko ts-node/bundler. Nie mieszaj importów type-only z runtime side effects. Lockfile, npm/pnpm audit, SBOM i minimalny obraz runtime ograniczają ryzyko supply chain.

7. Backend API i NestJS/Express

Controller mapuje HTTP na use case; validation pipe/DTO waliduje wejście, guard sprawdza auth, interceptor obsługuje cross-cutting concern, exception filter mapuje błędy na spójny kontrakt. W Nest singleton jest default: request-scoped provider zwiększa koszt i może propagować scope do zależnych providerów. Nie przechowuj current user w singletonie. W Express async error handling zależy od wersji, centralny middleware nie powinien ujawniać stacków. OpenAPI, pagination, idempotency, ETag/If-Match dla optimistic concurrency, 409/412 zgodnie z kontraktem. SQL parametryzowany, allowlist dynamicznych pól sortowania; ograniczenia body i rate per tenant. Dla background jobs nie uruchamiaj nieawaitowanej pracy po wysłaniu odpowiedzi; trwałe przyjęcie do kolejki/outbox. Transakcje · Resilience.
