Integracje SAP w systemie mikroserwisowym

Kontrakty, niezawodność, mapowanie i diagnostyka

1. Protokoły i ownership2. Syntetyczny przykład zlecenia3. Błędy, retry, reconcile4. Dane i bezpieczeństwo
Zagadnienie 1 / 4

Protokoły i ownership

SAP może udostępniać OData/REST, SOAP, RFC/BAPI lub middleware. Najpierw ustal konkretny interfejs, właściciela danych, SLA i semantykę operacji.

Praktyka / decyzja projektowa

Strangler/ACL adapter: przyjmuj własny kanoniczny command i tłumacz go na kontrakt systemu SAP; mapowania utrzymuj jawnie i wersjonuj.

Zagadnienie 2 / 4

Syntetyczny przykład zlecenia

Order service zapisuje intencję i outbox; worker wysyła command do SAP z correlationId; zapisuje status i external reference. HTTP 202 nie oznacza sukcesu w SAP.

Praktyka / decyzja projektowa

Stan: PENDING → SENT → CONFIRMED/REJECTED; awaria transportu → RETRY. Po przekroczeniu limitu DLQ i manual reconciliation.

Zagadnienie 3 / 4

Błędy, retry, reconcile

Oddziel błędy 4xx/validation od throttlingu, 5xx i timeoutów. Po timeout nie wiesz, czy SAP wykonał operację; sprawdź status przed ponowieniem.

Praktyka / decyzja projektowa

Stwórz dashboard zaległych transakcji, retry count, age i mismatch; zaplanuj replay bez podwójnego zaksięgowania.

Zagadnienie 4 / 4

Dane i bezpieczeństwo

Kontrakt: format dat, strefy czasowe, jednostki miary, waluty, identyfikatory, nullability; logowanie bez PII i credentiali.

Praktyka / decyzja projektowa

Contract tests na fixtures ze strony SAP, sandbox integration tests oraz testy przypadków partial failures.
